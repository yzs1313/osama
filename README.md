# موقع OSAMAH الرسمي

موقع فيه 3 صفحات: **البثوث** و**التعليقات** و**الأخبار**، مع تسجيل دخول بالإيميل، وقاعدة بيانات SQLite، ولوحة مشرفين.

## النشر على Vercel (مع ريبو GitHub)
Vercel ما فيها قرص دائم ولا عمليات تشتغل بالخلفية، فالمشروع صار يشتغل بقاعدة بيانات سحابية اسمها **Turso** (SQLite سحابي، مجاني للبداية)، والكود نفسه يشتغل محلياً وعلى VPS بدون تغيير (ملف `data.db` إذا ما حطيت إعدادات Turso).

**1) أنشئ قاعدة Turso** (من https://turso.tech أو من الـ CLI):
```
turso auth login
turso db create osama
turso db show osama --url          # ينسخ الرابط: libsql://...
turso db tokens create osama       # ينسخ التوكن
```

**2) انقل بياناتك الحالية من `data.db`** (اختياري، لو عندك بيانات تبي تبقى: مستخدمين، أخبار، سوشل، دسكورد...):
ضع ملف `data.db` في مجلد المشروع (مع `data.db-wal` و`data.db-shm` إذا موجودين بجانبه) ثم:
```
npm install
# Mac / Linux:
TURSO_DATABASE_URL="libsql://..." TURSO_AUTH_TOKEN="..." node scripts/copy-db.js ./data.db
# Windows PowerShell:
$env:TURSO_DATABASE_URL="libsql://..."; $env:TURSO_AUTH_TOKEN="..."; node scripts/copy-db.js ./data.db
```
(الجلسات ما تُنسخ، فكل واحد يسجّل دخوله من جديد مرة وحدة.)

**3) ارفع المشروع على الريبو** (الملفات `.env` و`data.db` ممنوعة تلقائياً في `.gitignore`، لا ترفعها أبداً):
```
git init
git add .
git commit -m "OSAMAH site"
git branch -M main
git remote add origin https://github.com/yzs1313/osama.git
git push -u origin main
```

**4) على Vercel:** New Project ثم اختر الريبو. اترك Framework على **Other**، وبدون Build Command. قبل ما تضغط Deploy أضف المتغيرات (Settings ثم Environment Variables):

| المتغير | الوصف |
|---|---|
| `TURSO_DATABASE_URL` / `TURSO_AUTH_TOKEN` | من الخطوة 1 (مطلوبة) |
| `ADMIN_EMAILS` | إيميلك (يصير مشرف) |
| `KICK_CLIENT_ID` / `KICK_CLIENT_SECRET` / `KICK_CHANNELS` | ربط Kick |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | الدخول عبر Google |
| `DISCORD_CLIENT_ID` / `DISCORD_CLIENT_SECRET` / `ADMIN_DISCORD_IDS` | الدخول عبر Discord |
| `SUPPORT_EMAIL` / `SUPPORT_DISCORD` | أزرار الدعم المباشر |

بعد النشر يطلع لك رابط `https://اسم-المشروع.vercel.app`، وتقدر تربط دومينك من Settings ثم Domains. أي تعديل تسويه وتعمل له `git push` يتنشر تلقائياً.

**كيف يختلف Kick على Vercel:** ما فيه عملية بالخلفية، فالموقع يفحص Kick "عند الطلب": أي زائر مفتوح عنده الموقع يحدّث كل 20 ثانية، والسيرفر يفحص Kick كل 30 ثانية بحد أقصى. يعني التنبيه يظهر خلال دقيقة تقريباً من بداية البث **إذا أحد فاتح الموقع**، ولو ما أحد داخل، أول زائر يفتح الموقع يشغّل الفحص ويشوف البث الحالي مباشرة. (Vercel Cron في الخطة المجانية مرة باليوم فقط، فما ينفع هنا.)

## تسجيل الدخول عبر Google
يظهر زر **المتابعة عبر Google** في نافذة الدخول إذا ضبطت الإعدادات:
1. افتح https://console.cloud.google.com وأنشئ مشروع (أو اختر مشروع موجود).
2. **APIs & Services ثم OAuth consent screen**: اختر **External**، اكتب اسم التطبيق وإيميل الدعم، وأضف نطاق موقعك. النطاقات المطلوبة الأساسية فقط (`openid`, `email`, `profile`) وما تحتاج مراجعة من Google.
3. **Credentials ثم Create Credentials ثم OAuth client ID**: النوع **Web application**.
4. في **Authorized redirect URIs** أضف بالضبط: `https://دومينك/api/auth/google/callback` (وللتجربة المحلية: `http://localhost:3000/api/auth/google/callback`).
5. انسخ **Client ID** و**Client Secret** وحطهم في `GOOGLE_CLIENT_ID` و`GOOGLE_CLIENT_SECRET` (على Vercel من Environment Variables ثم أعد النشر).
6. مهم: طالما التطبيق بحالة **Testing** يدخل فيه فقط الحسابات المضافة كـ Test users. اضغط **Publish app** عشان يدخل أي أحد.

**كيف يتصرف:**
- الإيميل من Google مؤكد دايماً، فلو الشخص عنده حساب مسجّل مسبقاً بنفس الإيميل بالباسورد، يندمج الحساب مع Google: يحتفظ بتعليقاته وصلاحياته، لكن **الباسورد القديم يتعطل** ويطلع من كل أجهزته (هذا يمنع أي أحد سجّل بإيميل غيره). بعدها يدخل بـ Google دايماً.
- أي إيميل Google موجود في `ADMIN_EMAILS` يصير مشرف تلقائياً. فلو سجّلت دخولك بـ Google بإيميلك تصير مشرف بدون باسورد.
- لو عندك روابط معاينة من Vercel (preview) أو أكثر من دومين، كل رابط لازم يتسجل في Authorized redirect URIs، أو حدّد رابطاً ثابتاً بـ `GOOGLE_REDIRECT_URI`.

## التشغيل على جهازك
1. ثبّت Node.js (نسخة 18 أو أحدث) من https://nodejs.org
2. افتح الترمنال داخل مجلد المشروع ونفّذ:
   ```
   npm install
   cp .env.example .env
   ```
3. افتح ملف `.env` وحط إيميلك في `ADMIN_EMAILS` (تقدر تحط أكثر من إيميل وتفصل بينها بفاصلة).
4. شغّل الموقع:
   ```
   npm start
   ```
5. افتح http://localhost:3000 وسجّل حساب جديد **بنفس الإيميل** اللي حطيته في `.env`، وبيصير مشرف تلقائياً.

## الصلاحيات
- **الزائر:** يشوف البثوث والأخبار والتعليقات.
- **العضو المسجّل:** يكتب تعليقات ويحذف تعليقاته.
- **المشرف:** يضيف ويحذف البثوث والأخبار، ينهي البث، يحذف أي تعليق، ويرقّي الأعضاء لمشرفين من تبويب "المستخدمين".

الصلاحيات مفحوصة في السيرفر، فحتى لو أحد حاول يرسل طلب بدون الواجهة ما يمر.

## اللغة (عربي / English)
زر **EN / عربي** أعلى الصفحة يبدّل لغة الموقع كاملة، ويقلب الاتجاه تلقائياً (RTL للعربي، LTR للإنجليزي). اختيار الزائر ينحفظ في متصفحه، واللغة الافتراضية العربية. رسائل الأخطاء من السيرفر تتبدل معها.
- نصوص الواجهة والترجمات في `public/i18n.js` (المفتاح عربي والقيمة إنجليزية). لتعديل أي ترجمة أو إضافة لغة عدّل هذا الملف.
- المحتوى اللي يكتبه المشرفون (عناوين البثوث والأخبار) والتعليقات يظهر بلغته الأصلية ولا يُترجم تلقائياً.

## قسم الدسكورد
تبويب "دسكورد" يعرض فريق الإدارة حسب الفئات (الإدارة العليا، المبرمجين، الوسطى، الصغرى). المشرف يضيف العضو (اسم + رابط اختياري + الفئة) ويحذفه من نفس التبويب.

## السوشل
تبويب "سوشل" يعرض حسابات OSAMAH (Kick، Twitch، YouTube، X، Instagram، TikTok، Snapchat، Discord، Telegram، WhatsApp، Facebook، أو رابط عام). المشرف يضيف ويحذف الحسابات من نفس التبويب، والزوار يشوفونها ويفتحونها.

## تسجيل الدخول عبر Discord
يظهر زر **المتابعة عبر Discord** في نافذة تسجيل الدخول، ويسجّل الزائر أو ينشئ له حساب بضغطة وحدة. ما يظهر الزر إلا إذا ضبطت الإعدادات تحت.

**الإعداد (مرة وحدة):**
1. افتح https://discord.com/developers/applications وسوّ **New Application**.
2. من **OAuth2** انسخ **Client ID** و**Client Secret**.
3. في **OAuth2 ثم Redirects** أضف الرابط `https://دومينك/api/auth/discord/callback` (بالضبط، بنفس الدومين وبـ https).
4. حط القيم في `.env`: `DISCORD_CLIENT_ID` و`DISCORD_CLIENT_SECRET`، ثم `pm2 restart osamah`.
   - لو ما اشتغل الرابط تلقائياً خلف البروكسي، حدده يدوياً في `DISCORD_REDIRECT_URI`.

**كيف يشتغل:**
- حساب Discord ينشأ بالاسم الظاهر عنده. الإيميل ينحفظ فقط إذا كان **مؤكد** في Discord وغير مستخدم عندنا، وإلا ينشأ الحساب بدون إيميل (يظهر في لوحة المشرف بأيقونة Discord).
- ما نربط حساب Discord بحساب موجود بنفس الإيميل تلقائياً (لأن إيميلات التسجيل العادي غير مؤكدة، وهذا يمنع أحد يسرق حساب غيره). فمن سجّل بالإيميل أول مرة وبعدين دخل بـ Discord يكون عنده حسابين.
- لجعل حساب Discord مشرف: حط رقمه (ID) في `ADMIN_DISCORD_IDS` في `.env` (افصل بفاصلة). كذلك أي حساب Discord إيميله المؤكد موجود في `ADMIN_EMAILS` يصير مشرف.
- حسابات Discord ما لها باسورد، فما تظهر لها "إعادة تعيين الباسورد" عند المشرف.

## الأيقونات
كل الإيموجي استُبدلت بأيقونات SVG مضمّنة في الصفحة (بدون مكتبات خارجية ولا طلبات إضافية): أيقونات الواجهة من Lucide (ISC)، وشعارات المنصات من Simple Icons (CC0). كلها في `public/icons.js`، وتاخذ لون النص تلقائياً. لإضافة أيقونة جديدة ضيف سطرها في `ICONS` واستخدم `ico("الاسم")`.

## القلوب وإدارة المستخدمين
- **القلوب ❤️:** كل عضو مسجّل يقدر يحط قلب على أي تعليق (ضغطة تحط وضغطة ترجّع)، والعدد يظهر للكل.
- **تبويب المستخدمين (للمشرفين):**
  - بحث بالاسم أو الإيميل.
  - ترقية لمشرف أو إزالة الإشراف.
  - **إعادة تعيين الباسورد:** يتولّد باسورد مؤقت (12 خانة) يظهر لك مرة وحدة، انسخه وأعطه للمستخدم. المستخدم يطلع من كل أجهزته، والباسورد القديم ما يشتغل.
  - **حذف مستخدم:** يحذف حسابه وكل تعليقاته وقلوبه (ما ينرجع). ما تقدر تحذف نفسك.
- ما فيه حالياً صفحة يغيّر فيها العضو باسورده بنفسه، التغيير يتم عن طريق المشرف.

## الدعم الفني
زر **💬 الدعم** عائم أسفل يمين الشاشة وظاهر في كل الصفحات، يفتح نافذة فيها نموذج تواصل (الاسم، الإيميل، العنوان، الرسالة) يقدر يرسله أي زائر. الرسائل تنحفظ كتذاكر في قاعدة البيانات.
- **المشرف** يشوفها في تبويب "التذاكر" (يظهر عدد المفتوحة)، ويرد عليها، أو يغلقها، أو يحذفها، أو يرد على إيميل صاحبها بضغطة.
- **العضو المسجّل** يشوف رسائله وردود الدعم في نفس الصفحة. الزائر غير المسجّل يوصله الرد على إيميله يدوياً من المشرف.
- حماية من السبام: كل جهاز (وكل حساب) يرسل رسالة وحدة كل 6 ساعات، ومحفوظ في القاعدة فما ينمسح بإعادة التشغيل. لتغيير المدة عدّل `SUPPORT_COOLDOWN` في `server.js`.
- تقدر تعرض أزرار تواصل مباشر (إيميل أو ديسكورد) بتعبئة `SUPPORT_EMAIL` و`SUPPORT_DISCORD` في `.env`.
- الموقع ما يرسل إشعار بالإيميل للمشرف عند وصول تذكرة جديدة، يشوفها في التبويب.

## ربط Kick (تنبيه البث التلقائي)
الموقع يفحص قنوات Kick المربوطة عند الطلب (كل 30 ثانية بحد أقصى، طالما أحد فاتح الموقع). أول ما يبدأ البث:
- يطلع شريط أحمر "يبث الآن" فوق الموقع، ويتغير عنوان التبويب.
- ينزل البث تلقائياً في صفحة البثوث برابط القناة، وينتهي لحاله لما يخلص البث.
- المتصفحات المفتوحة تتحدث لحالها كل 20 ثانية بدون إعادة تحميل، وهذي نفسها اللي تشغّل فحص Kick.

**الإعداد:**
1. من حسابك في Kick: الإعدادات ثم تبويب Developer، أنشئ تطبيق (قد يطلب تفعيل التحقق بخطوتين) وخذ **Client ID** و**Client Secret**.
2. حطهم في `.env` في `KICK_CLIENT_ID` و`KICK_CLIENT_SECRET`.
3. حدد اليوزرات في `KICK_CHANNELS` (أو أضفها بعدين من تبويب "ربط Kick" في لوحة المشرف، وتقدر تلصق رابط القناة).
4. أعد تشغيل السيرفر.

اسم الستريمر: شريط "يبث الآن" وكرت البث يعرضون اسم صاحب البث (يوزر قناته في Kick). لو أكثر من شخص يبث بنفس الوقت يطلع لكل واحد شريط خاص فيه. وللبث اللي تضيفه يدوياً فيه خانة "اسم الستريمر" (إذا تركتها فاضية يطلع OSAMAH).

ملاحظات: Kick يتأخر أحياناً ثواني في تحديث الحالة، فالموقع ما ينهي البث إلا بعد فحصين متتاليين "غير مباشر". والمشرف يقدر ينهي أي بث يدوياً ولا يرجع.

## النشر برابط عام على استضافتك
الموقع تطبيق Node.js، فيحتاج استضافة تدعم Node (VPS أو Node.js App في cPanel أو Render/Railway...). الاستضافة اللي تدعم PHP بس ما تشغّله.

**على VPS (Ubuntu مثلاً):**
```
# ارفع المجلد (بدون node_modules) ثم:
cd osamah-site && npm install --omit=dev
cp .env.example .env && nano .env      # عدّل القيم، وخلي NODE_ENV=production
npm i -g pm2 && pm2 start server.js --name osamah && pm2 save && pm2 startup
```
بعدها وجّه الدومين على المنفذ 3000 عبر Nginx أو Caddy وفعّل HTTPS (مثلاً `caddy reverse-proxy --from yourdomain.com --to :3000`).

**على cPanel:** من Setup Node.js App اختر مجلد المشروع وملف التشغيل `server.js`، ثم Run NPM Install، وضيف المتغيرات في Environment variables.

لازم HTTPS مع `NODE_ENV=production`، وإلا ما يثبت تسجيل الدخول. وخذ نسخة احتياطية دورية من `data.db`.

## الملفات
- `server.js` — السيرفر وتسجيل الدخول (إيميل / Discord / Google)
- `lib/db.js` — قاعدة البيانات (libSQL: ملف محلي أو Turso)
- `api/index.js` و`vercel.json` — إعدادات Vercel
- `scripts/copy-db.js` — نقل بياناتك من `data.db` إلى Turso
- `kick.js` — الربط مع Kick
- `public/` — واجهة الموقع (`index.html`, `style.css`, `app.js`, `i18n.js`, `icons.js`, `hero.jpg`)
- `data.db` — قاعدة البيانات المحلية (تنشأ تلقائياً أول تشغيل إذا ما حطيت إعدادات Turso، لا ترفعها على GitHub)

## النشر على استضافة
يشتغل على أي استضافة Node مثل Render أو Railway أو VPS:
- أمر التشغيل: `npm start`
- ضبط المتغيرات: `ADMIN_EMAILS` و`NODE_ENV=production`
- مهم: القاعدة ملف على القرص، فاستخدم **قرص دائم (Persistent Disk/Volume)** وحدد مساره بـ `DB_FILE=/المسار/data.db`، وإلا تنمسح البيانات مع كل نشر.
- لازم HTTPS عشان الكوكيز الآمنة تشتغل في وضع production.

## ملاحظات
- ما فيه تأكيد للإيميل ولا استرجاع كلمة المرور (يحتاج خدمة إرسال بريد مثل SMTP). أقدر أضيفها لك.
- لتغيير اسم الشخص أو الألوان: `public/index.html` و`public/style.css`.
- لتغيير صورة الهيدر: استبدل `public/hero.jpg`.
